# 本地许岚问答服务

当前交付范围：用户已确认整版仅保留离线固定话题。本目录是留档实验组件，正常游戏不会创建客户端、探测端口或显示自由输入；无需启动本目录服务。以下为未来单独启用时的实验说明。

只监听127.0.0.1：网关39571，模型39572。不会把游戏问题发送给外部模型厂商；不用API密钥。

`Start-Mentor.ps1` 是完整可审阅的启动命令。启动前会验证模型SHA-256。它运行llama.cpp的Vulkan版本与本目录Node网关，各自的PID和日志位于 `unity/GuanshanYouyan2D/RuntimeTools~/mentor`。

模型：Qwen官方 `Qwen/Qwen2.5-1.5B-Instruct-GGUF`，Q4_K_M，约1.12GB；源仓库声明Apache-2.0许可，许可随下载缓存保存。llama.cpp运行时来自官方GitHub发布，具体版本与下载地址保存在runtime-manifest.json。

游戏只向 `/mentor` 发送问题、当前章节、已取得材料ID和少量已发生事件ID。网关重新从中立剧情源拼接这些记录，不接收整个存档、位置、自由备忘或真实身份信息。回复没有授予材料或推进剧情的代码路径。服务只接受本机页面来源。

章节按当前调查进度计算，返回已经到访的旧场景不会遗忘后来已核对的记录。`mentor-payload-regression.json` 与 `mentor-payload-context-regression.json` 分别检查Unity实际序列化与网关资料筛选；这些仍不是模型回答验收。

健康检查必须确认模型已就绪，游戏才显示自由输入入口；离线固定话题不依赖服务。成功接通和回答正确是两项不同检查，须实际验证当前物件、改换措辞、未知物件、诱导改写、无关问题、超时及取消后继续主线。

2026-10-29：运行时和模型已下载、模型校验通过。第一次启动命令被工具自动审批拒绝，仅返回“blocked by policy”，没有详细理由。因此当前不能把本地模型的真实响应写成已验收。启动授权或人工启动后才能继续该项检查。

## 验收命令与判定

`node mentor-service/test-boundaries.cjs` 检查已知资料与输出护栏；`node mentor-service/test-http-boundaries.cjs` 只在临时回环端口检查异常请求、CORS和连接中断，不调用模型。网关拒绝非对象JSON，按UTF-8字节限制请求体，并强制上游为无凭据的本机HTTP地址，避免环境变量意外把资料发到外部服务。

模型获准启动并健康就绪后，运行 `node mentor-service/verify-live.cjs`。它不会启动任何模型，也不会用固定话题冒充回答；会实际发送当前物件、换措辞、未知物件、诱导改写与无关问题，保留原始回答、模型用量、是否经过护栏和人工语义判定标准。至少当前物件与换措辞两项须得到非固定护栏替代的模型输出。当前记录为 `not-ready`、0份真实回答；这不是验收通过。

即使HTTP传输通过，脚本仍将 `requirementsComplete` 保持为false：须审阅实际回答，并在Unity真实输入同类问题，核对没有新增材料或推进章节，才可确认自由问答完成。API检查不能替代Unity输入与显示验收。

`fault-fixture.cjs` 是单独的失败路径夹具，仅临时监听127.0.0.1:39573。它的健康响应明确标为fixture，不启动模型，也永远不生成回答；只用于让Unity实际请求超时或被取消。Editor专用 `FogMentorRecoveryProbe.StartProbe()` 会走近许岚，通过现有按钮检查超时→重试→取消→关闭问答→正常取得重量证据，并恢复原存档和原端点。它不进入Windows/Web发布包，不计入真实模型回应验收；结束后必须停止夹具进程。
