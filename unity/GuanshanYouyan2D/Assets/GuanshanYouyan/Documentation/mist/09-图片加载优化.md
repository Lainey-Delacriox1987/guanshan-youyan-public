# 图片加载优化（v3.0.1）

日期：2026-10-26。用户报告Chrome/微信中PNG背景按扫描行显示，等待一至两分钟仍只加载半幅。

## 根因与修改

四张原始PNG共9,801,111字节，单张2.05–2.89MB；地图、线索板和人物也引用大图。改为独立的1536px桌面WebP、960px手机WebP与480px缩略图，文件名含内容哈希。原始PNG保留，不改变构图。

背景先显示内嵌的小型模糊预览，图片下载并decode完成后显示清晰层；解码前清晰层透明。保留已解码Image对象，避免切换界面重复解码/下载；同URL请求去重。只在现场/章节开场空闲时低优先级预取下一幕，弱网或省流模式不预取。首页按相同屏宽规则预载资源，防止预载和实际显示选择两张不同图片。

地图与线索板使用独立小图，总计约100KB。Netlify _headers为带内容哈希的WebP设置一年immutable浏览器缓存，HTML/脚本/样式每次发布后可重验证。存档key与schema保持原样。

## 验证

43项核心与媒体逻辑测试通过。四关及双结局浏览器验收35项通过，无JS错误、离线请求失败。独立慢网浏览器测试：320 kbit/s下载、180ms延迟、禁用缓存。仓库清晰图4.914秒，手机冷启动首页6.246秒；原始PNG请求0、重复主图请求0。弱网完成前整幅模糊预览可见，清晰层opacity=0；解码完成才切换。以上是本地服务器受控网络模拟，不代表对所有公网线路的时延保证。

脚本：tools/optimize-mist-art.cjs、tests/media.test.cjs、tests/browser-loading.cjs。报告与截图：output/mist-image-optimization.json、output/mist-loading-check/。WebP仅是原画的交付编码，非重新生成美术。

缓存配置依据：https://docs.netlify.com/manage/routing/headers/ 和 https://developers.netlify.com/guides/advanced-caching-made-easy/ 。
